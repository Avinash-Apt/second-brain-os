# Context

Foundational documents about the operator and the business. Every other part of the vault leans on these.

| File | Purpose |
|---|---|
| `me.md` | Operator identity, working style, how they want to be challenged, unclosed loops |
| `business.md` | What the company does, stage, model, differentiation |
| `services.md` | Offers, who they're for, delivery process |
| `icp.md` | Ideal customer profile |
| `pain-points.md` | Customer pains in their own words, and how we address them |
| `infrastructure.md` | Tool stack, connectors, which tool is source of truth for what |
| `brand.md` | Voice, tone, words to use and avoid |
| `team.md` | Team roster, ownership, external partners |
| `strategy.md` | 12-month goal, quarterly priorities, what we're saying no to |

## Rules

- These files are authoritative. Do not duplicate their content elsewhere; link to them.
- Delete a file (and its row in the root routing table) if it doesn't apply, rather than leaving placeholders.
- Update in place when facts change, and add `updated: YYYY-MM-DD` to the frontmatter.
- Tool stack changes go to `infrastructure.md` immediately, including connector name and date verified. Never secrets.
- No hard financial figures in these files (root Rule 16). Structure, ratios and trends only.
- The weekly optimizer flags goals in `strategy.md` with no active project.
